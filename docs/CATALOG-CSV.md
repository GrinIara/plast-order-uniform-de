# Опублікований CSV: структура і розташування

## 1. Де це лежить
- **Один Google Sheet «plast-uniform-catalog»** на Google Drive спільного акаунту станиці (або Shared Drive), доступ редактора мають усі координатори.
- У ньому три листи: `catalog`, `synonyms`, `settings`. Таблиця відповідей **окремий файл** (її пише прихований Google Form) і приватна.
- Кожен лист публікується окремо: *Файл → Поділитися → Опублікувати в Інтернеті → обрати лист → формат CSV*. Google дає кожному листу своє посилання:
  `https://docs.google.com/spreadsheets/d/e/<PUBLISH_ID>/pub?gid=<GID>&single=true&output=csv`
- Ці три посилання зберігаються в GitHub Actions Variable `SITE_CONFIG` (§6), а не в репозиторії. Вони публічні за задумом: потрапляють у збірку сайту й видимі через DevTools. `PUBLISH_ID` не збігається з ID самої таблиці і не дає доступу на редагування.
- Опублікована версія оновлюється автоматично після змін (з кешем у кілька хвилин). Увімкніть «Автоматично повторно публікувати».
- Все, що лежить на цих листах, **читає будь-хто з посиланням**. Особисті дані туди не пишемо.
- Знімок: щодня Action завантажує три CSV, валідує їх і кладе в збірку як `catalog.json` (не комітиться в git). Сайт використовує його, якщо Google недоступний.

## 2. Загальні правила
- Один заголовковий рядок з англійськими назвами колонок точно як нижче; порядок колонок не важливий, зайві колонки ігноруються.
- Без об'єднаних клітинок, порожніх рядків між даними й формул, що повертають помилки (`#N/A`).
- Дати `YYYY-MM-DD`. Ціна з крапкою, без символу валюти (`24.90`). Валюта EUR задається в `settings`.
- Кодування UTF-8. Клітинки з комами Google сам бере в лапки.

## 3. Лист `catalog` (один рядок на розмір)

| колонка | обов'язкова | правило |
|---|---|---|
| product_id | так | спільний для розмірів, `[A-Z0-9-]+` |
| sku | так | унікальний, `product_id` + розмір |
| name_uk | так | назва |
| name_de | ні | німецька назва |
| category | так | напр. `Сорочки` |
| synonyms | ні | через кому |
| size | так | `S`, `M`, `L`, `128`, `one size` тощо |
| stock | ні | порожньо, `немає` або `під замовлення` |
| price | ні | десяткове число |
| source_url | так | `https://` на scoutstyle.net |
| updated_at | так | дата |

Приклад:
```csv
product_id,sku,name_uk,name_de,category,synonyms,size,stock,price,source_url,updated_at
UPP-SHIRT,UPP-SHIRT-S,Сорочка УПП,UPP-Hemd,Сорочки,"УПП, повсякденна, сорочка",S,,24.90,https://scoutstyle.net/...,2026-10-01
UPP-SHIRT,UPP-SHIRT-M,Сорочка УПП,UPP-Hemd,Сорочки,"УПП, повсякденна, сорочка",M,під замовлення,24.90,https://scoutstyle.net/...,2026-10-01
UPP-SHIRT,UPP-SHIRT-L,Сорочка УПП,UPP-Hemd,Сорочки,"УПП, повсякденна, сорочка",L,немає,24.90,https://scoutstyle.net/...,2026-10-01
```
Помилки рядка (немає `sku`, дубль `sku`, невідомий `stock`, `source_url` не `https://`, некоректна дата) призводять до того, що рядок пропускається, а номер виводиться в консоль.

## 4. Лист `synonyms`
Один рядок = група взаємозамінних слів; пошук за будь-яким знаходить усі.

| колонка | правило |
|---|---|
| group | довільна мітка, напр. `uniform` |
| terms | слова через кому (UA і DE) |

```csv
group,terms
uniform,"однострій, УПП, форма, Uniform, Kluft"
shirt,"сорочка, сорочки, Hemd"
```

## 5. Лист `settings` (ключ — значення)
Редагується координаторами без коду. Усі значення публічні.

```csv
key,value
currency,EUR
recipient,Plast Düsseldorf e.V.
iban,DE00 0000 0000 0000 0000 00
bic,XXXXXXXX
purpose_hint,Однострій
payment_note,"Суму повідомить координатор за вашим телефоном."
```
Сайт показує `recipient`, `iban`, `bic`, `payment_note`, а призначення платежу складає як `<purpose_hint> – Прізвище Ім'я` (якщо `purpose_hint` порожній, використовується «Однострій») у Zusammenfassung, після «Відправити» та в FAQ. 

## 6. Конфігурація станиці: Variable `SITE_CONFIG`
Значення (JSON) вставляється в Settings → Secrets and variables → Actions → Variables. Під час збірки Action записує його в `dist/config.json`. У репозиторії лежить лише `config.example.json` із заглушками такої самої схеми.
```json
{
  "station": "Düsseldorf",
  "basePath": "/plast-order-uniform-de/",
  "csv": { "catalog": "https://…output=csv", "synonyms": "https://…output=csv", "settings": "https://…output=csv" },
  "form": { "action": "https://docs.google.com/forms/d/e/…/formResponse", "fields": { "firstName": "entry.111", "lastName": "entry.222", "phone": "entry.333", "station": "entry.444", "uladh": "entry.777", "unit": "entry.888", "order": "entry.555", "consent": "entry.666" } },
  "coordinators": [{ "name": "…", "phone": "+49 …", "email": "…" }]
}
```
У `SITE_CONFIG` лише посилання, ідентифікатори й публічні контакти координаторів, без IBAN (він у листі `settings`). Адреси для сповіщень Action (`notify`) винесено з цього JSON в окрему Variable `NOTIFY_EMAILS`, щоб вони не потрапили на сайт.

## 7. Прихований Google Form і таблиця відповідей
Сайт сам збирає дані й надсилає їх POST-запитом на `form.action`. Поля Google Form (обов'язкові, крім підрозділу): ім'я, прізвище, телефон, станиця, улад (одне зі значень: `Пташата`, `УПН`, `УПЮ`, `УСП`, `УПС`), підрозділ (довільний текст; у Google Form необов'язкове поле), «Замовлення» (довгий текст), згода (поле для значення чекбокса). Форма не публікується, її посилання ніде не рекламується. Якщо поле у формі перейменовувати або перестворювати, треба оновити `entry.*` у `SITE_CONFIG`. Ім'я, прізвище й телефон зберігаються лише в таблиці відповідей, що доступна координаторам.

## 8. Що перевірити перед стартом
- Чи віддає опублікований CSV заголовки CORS для `fetch` з GitHub Pages (у Sheets зазвичай так; перевірити на тестовій таблиці).
- Затримка між правкою і відображенням в опублікованому CSV.
- Що публікуються лише листи `catalog`, `synonyms`, `settings`, а не вся книга.
